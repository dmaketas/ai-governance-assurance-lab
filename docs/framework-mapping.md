# Framework mapping

This project uses an original control taxonomy.

The controls are designed to be relatable to widely used AI governance, risk and security concepts without reproducing proprietary standard text.

## Conceptual alignment

| Lab domain | Typical governance/security concept |
|---|---|
| Governance | accountability, ownership, policy, risk acceptance |
| Data | data governance, quality, provenance, protection |
| Security | identity, access control, input security, application security |
| RAG Security | retrieval trust boundaries, authorization, data leakage prevention |
| Agent Security | tool authorization, excessive agency, approval gates |
| Model Risk | supplier risk, provenance, model changes |
| Evaluation | testing, validation, red teaming, misuse testing |
| Monitoring | logging, traceability, anomaly detection |
| Human Oversight | intervention, escalation, override |
| Privacy | minimization, retention, lawful handling |
| Incident Response | AI-specific incident preparation and response |
| Resilience | fallback, shutdown, recovery |
| Change Management | controlled changes to models, prompts, tools and data |

## Standards and frameworks

The lab can be extended with mappings to the official sources for:

- ISO/IEC 42001,
- NIST AI RMF,
- NIST Cybersecurity Framework,
- ISO/IEC 27001,
- privacy-management frameworks,
- OWASP guidance for LLM applications,
- MITRE ATLAS.

Such mappings should reference the official publications rather than copying protected control text into this repository.
